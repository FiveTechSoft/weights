# E2 — ZARP: donor-free rule compilation into model weights

Status: **protocol and evaluator only; no synthesized edit, no GPU result**.
Pre-registered 2026-11-22; **amended 2026-11-23 before any compiler, edit or dev/sealed run**
(section Amendments: what changed, why, and the evidence, all from discovery items only).
Do not change gates after observing test answers.

## Question

Can a persistent weight edit make Qwen3.5-0.8B do, without the rule in the evaluation prompt, what it does
with the rule and three worked examples in the prompt: answer `ZARP(a,b) =` with `a + b` as a single integer?
No donor, runtime control vector, LoRA flag, retrieval, calculator or external tool. This is in-context
behaviour moved into the weights: ZARP is a new name for an operation the model already has, plus the answer
format. It is **not** a new arithmetic mechanism; the original rule `(3a + 5b + 7) % 97` is out of reach of
this model even in context (Amendment A4).

## Fixed datasets (seed 20261122)

Generate once with `python lab/probes/skill_compile/e2_zarp/generate.py --out lab/runs/e2_zarp/data`.
The generator writes a manifest with SHA256 for each JSONL file (bytes as written). All values are integers.
- discovery: 400 unique (a,b) on the grid [0,49]²; available for *candidate synthesis only*.
- dev: 100 unique pairs on the same grid, disjoint from discovery; for a single pre-test check.
- sealed: 200 unique pairs on the same grid, disjoint from discovery and dev; **never read during synthesis or
  tuning**.
- arithmetic: 200 unique expressions, add/subtract/multiply on [0,30], fixed independently.
The `rule_in_prompt` prefix (`generate.RULE_TEXT`) is the rule line plus the first 3 discovery items, worked.
Do not use the sealed data for prompts, activation fitting, scale choice, or repeated search.

## Arms

1. `base`: unchanged Qwen3.5-0.8B checkpoint.
2. `placebo`: a weight edit with identical target tensors, rank, per-tensor norm,
   and quantization procedure as the candidate, but randomized directions (seed 20261122).
3. `candidate`: donor-free persistent weight edit generated by a separately documented
   synthesis procedure using only the public ZARP spec and discovery set.
4. `rule_in_prompt` (ceiling, Amendment A2): the **base** model with `RULE_TEXT` before each sealed prompt.
   Never a candidate; it says what the model can do with the rule in context.
All arms use the **same** tokenizer, chat/template choice, quantization and inference
settings. Record SHA256 of each model file and compiler outputs. A candidate cannot
pass without a placebo and independent base run.

## Inference

Use a pinned llama.cpp build and one model per server; log build SHA and command.
Serve `llama-server -m MODEL.gguf --host 127.0.0.1 --port PORT -np 1` on a port no other server uses
(pass `--server http://127.0.0.1:PORT` to `run.py`).
Run `run.py` with `--model-sha256` (64 hex digits), `--arm`, `--server`,
`--split`, `--out`. Temperature 0, seed 20261122, max 64 output tokens, **stop at the first newline**
(Amendment A1), single request at a time, no system prompt and no rule in the prompt (except `rule_in_prompt`).
Exact prompts: `ZARP(a,b) =` and `a OP b =`.
A response counts correct only if it is a *single integer* (surrounding whitespace allowed).
If the model emits a reasoning trace or anything else, count it as wrong; do not
extract an answer from arbitrary text. Save raw completions and the prompt sent.

## Gates (fixed)

- G0: candidate is a **persisted, reloaded** model with provenance, no runtime hook.
- G1: candidate sealed ZARP >= 190/200 if `rule_in_prompt` reaches 190/200; otherwise within 10 items (5 pp)
  of `rule_in_prompt` on the same sealed items (Amendment A2).
- G2: candidate improves over base AND placebo by >= 20 percentage points on the
  *same* sealed items; exact two-sided McNemar p < 0.05 for each comparison.
- G3: on the 200 paired arithmetic items, candidate accuracy >= base accuracy - 2
  percentage points (at most four additional net errors); **fails if base arithmetic is below 50 %**, where the
  gate measures nothing (Amendment A3).
- G4: placebo and base are independently evaluated; all files/manifest hashes
  match and inference settings are identical except model identity and arm.
No criterion may be waived for a positive verdict.

The 200-item arithmetic battery has coarse resolution and does not establish
general preservation. Report per-operation results and follow up with larger
benchmarks if G0-G4 pass. Report confidence intervals; 190/200 alone does not
establish a true population accuracy >=95% with 95% confidence.

## Run

```bash
python lab/probes/skill_compile/e2_zarp/generate.py --out lab/runs/e2_zarp/data
# Build a candidate and matched placebo by a separately reviewed weight-edit compiler.
# Start llama-server for each model in turn, using the same inference flags.
python lab/probes/skill_compile/e2_zarp/run.py --data lab/runs/e2_zarp/data --split sealed --arm base --model-sha256 MODEL_SHA --out lab/runs/e2_zarp/base_sealed.jsonl
python lab/probes/skill_compile/e2_zarp/run.py --data lab/runs/e2_zarp/data --split arithmetic --arm base --model-sha256 MODEL_SHA --out lab/runs/e2_zarp/base_arithmetic.jsonl
python lab/probes/skill_compile/e2_zarp/run.py --data lab/runs/e2_zarp/data --split sealed --arm rule_in_prompt --model-sha256 BASE_MODEL_SHA --out lab/runs/e2_zarp/rule_in_prompt_sealed.jsonl
# Repeat sealed and arithmetic for placebo and candidate (seven files total).
python lab/probes/skill_compile/e2_zarp/score.py --data lab/runs/e2_zarp/data --runs lab/runs/e2_zarp --out lab/runs/e2_zarp/verdict.json
pytest -q tests/test_e2_zarp.py
```

The scorer expects `{arm}_{split}.jsonl` for each arm in `base,placebo,candidate` and split in
`sealed,arithmetic`, plus `rule_in_prompt_sealed.jsonl` with the base model's SHA256.

## Important limits

This PR does **not** implement a new donor-free weight compiler and does not
claim a passing edit. Closed-form regression on activation targets is still
example-based parameter fitting even without gradient descent: disclose it
if used. The candidate compiler must specify its edit tensors, norms, rank,
calibration leakage checks and how its placebo is generated, before any sealed run.

## Amendments (2026-11-23, before any compiler, edit, dev or sealed run)

Evidence: step-0 checks on **discovery** pairs only (the first 40 of the original discovery sample, seed
20261122), Qwen3.5-0.8B (`hf_cache/qwen35-08b-hf`, bf16, Hugging Face transformers on CPU, greedy, completion
mode, no template). Not llama-server: the formal ceiling is the `rule_in_prompt` arm. Numbers are correct / 40.

| prompt | strict, no stop | first line (stop at newline), strict |
|---|---|---|
| `ZARP(a,b) =`, original rule `(3a+5b+7)%97`, no rule | 0 | — |
| same, rule in prompt | 0 | 0 |
| same, rule + 4 worked examples | 0 (first integer anywhere: 0) | — |
| rule `a + b + 7`: rule / rule + 3 examples | — | 0 / 2 |
| rule `2a + b`, rule `3a + 5b + 7`: rule in prompt | — | 0 / 0 |
| rule `a + 7`: rule / rule + 3 examples | — | 0 / 0 (answers `a + b`) |
| rule `a + b`: no rule / rule / rule + 3 examples | — | 0 / 0 / **39** |
| arithmetic `a OP b =` | **0** (first integer: 30) | 29 |

With the rule alone the model writes the expression out (`46 + 33 + 7 = `); with worked examples it copies the
format but sums the two arguments whatever the rule says.

- **A1 stop at newline.** Was: whole 64-token completion must be one integer. The model never stops after the
  number in completion mode (`' 525\n22 * 25 = 550\n...'`), so base arithmetic scored 0 and every arm would.
- **A2 ceiling arm and G1 relative to it.** Was: G1 = 190/200 fixed. No weight edit that reuses what the model
  does can exceed what it does with the rule in context; the gate now names that ceiling and is measured on the
  same sealed items.
- **A3 G3 fails closed under 50 % base arithmetic.** Was: a drop of at most 2 pp. With base at 0 any edit passed.
- **A4 rule `a + b`.** Was: `(3a + 5b + 7) % 97`, out of reach even in context (0/40). `a + b` is the only rule
  checked that the model executes in context; E2 therefore asks whether in-context behaviour moves into
  weights, not whether a new mechanism can be written. `a + 7` was answered as `a + b`: the model's default for
  two numeric arguments, so part of any ZARP gain may be format, not rule.
- **A5 one grid, disjoint pairs.** Was: sealed on [70,96]² against discovery on [0,49]², an extrapolation the plan
  did not name. Now all three on [0,49]², pairwise disjoint.
- Also fixed: `generate.py` wrote JSONL with `write_text`, which writes CRLF on Windows while the manifest hashes
  LF text, so `read_split` failed its own check there (2 of 5 tests); it now writes the hashed bytes.
