# E2 — ZARP: donor-free rule compilation into model weights

Status: **protocol and evaluator only; no synthesized edit, no GPU result**.
Pre-registered 2026-11-22. Do not change gates after observing test answers.

## Question

Can a persistent weight edit teach Qwen3.5-0.8B to answer `ZARP(a,b)=(3*a+5*b+7)%97`
without the rule in the evaluation prompt, without a donor, runtime control vector,
LoRA flag, retrieval, calculator, or external tool? This is an artificial rule;
success may be recombination of existing arithmetic, not a novel arithmetic mechanism.

## Fixed datasets (seed 20261122)

Generate once with `python lab/probes/skill_compile/e2_zarp/generate.py --out lab/runs/e2_zarp/data`.
The generator writes a manifest with SHA256 for each JSONL file. All values are integers.
- discovery: 400 unique (a,b), each in [0,49]; available for *candidate synthesis only*.
- dev: 100 unique pairs, a in [50,69], b in [0,69]; for a single pre-test check.
- sealed: 200 unique pairs, a and b in [70,96]; **never read during synthesis or tuning**.
- arithmetic: 200 unique expressions, add/subtract/multiply on [0,30], fixed independently.
All items are deterministic; sealed is disjoint in both input coordinates from discovery.
Do not use the sealed data for prompts, activation fitting, scale choice, or repeated search.

## Arms

1. `base`: unchanged Qwen3.5-0.8B checkpoint.
2. `placebo`: a weight edit with identical target tensors, rank, per-tensor norm,
   and quantization procedure as the candidate, but randomized directions (seed 20261122).
3. `candidate`: donor-free persistent weight edit generated by a separately documented
   synthesis procedure using only the public ZARP spec and discovery set.
All arms use the **same** tokenizer, chat/template choice, quantization and inference
settings. Record SHA256 of each model file and compiler outputs. A candidate cannot
pass without a placebo and independent base run.

## Inference

Use a pinned llama.cpp build and one model per server; log build SHA and command.
Serve `llama-server -m MODEL.gguf --host 127.0.0.1 --port 8080 -np 1`.
Run `run.py` with `--model-sha256` (64 hex digits), `--arm`, `--server`,
`--split`, `--out`. Temperature 0, seed 20261122, max 64 output tokens,
single request at a time, no system prompt and no rule in the prompt.
Exact prompts: `ZARP(a,b) =` and `a OP b =`.
A response counts correct only if it is a *single integer* (surrounding whitespace allowed).
If the model emits a reasoning trace or anything else, count it as wrong; do not
extract an answer from arbitrary text. Save raw completions.

## Gates (fixed)

- G0: candidate is a **persisted, reloaded** model with provenance, no runtime hook.
- G1: candidate sealed ZARP >= 190/200 (95%).
- G2: candidate improves over base AND placebo by >= 20 percentage points on the
  *same* sealed items; exact two-sided McNemar p < 0.05 for each comparison.
- G3: on the 200 paired arithmetic items, candidate accuracy >= base accuracy - 2
  percentage points (at most four additional net errors).
- G4: placebo and base are independently evaluated; all files/manifest hashes
  match and inference settings are identical except model identity and arm.
No criterion may be waived for a positive verdict.

The 200-item arithmetic battery has coarse resolution and does not establish
general preservation. Report per-operation results and follow up with larger
benchmarks if G0-G4 pass. Report confidence intervals; 190/200 alone does not
establish a true population accuracy >=95% with 95% confidence.

## Run

```bash
python lab/probes/skill_compile/e2_zarp/generate.py --out lab/runs/e2_zarp/data
# Build a candidate and matched placebo by a separately reviewed weight-edit compiler.
# Start llama-server for each model in turn, using the same inference flags.
python lab/probes/skill_compile/e2_zarp/run.py --data lab/runs/e2_zarp/data --split sealed --arm base --model-sha256 MODEL_SHA --out lab/runs/e2_zarp/base_sealed.jsonl
python lab/probes/skill_compile/e2_zarp/run.py --data lab/runs/e2_zarp/data --split arithmetic --arm base --model-sha256 MODEL_SHA --out lab/runs/e2_zarp/base_arithmetic.jsonl
# Repeat sealed and arithmetic for placebo and candidate (six files total).
python lab/probes/skill_compile/e2_zarp/score.py --data lab/runs/e2_zarp/data --runs lab/runs/e2_zarp --out lab/runs/e2_zarp/verdict.json
pytest -q tests/test_e2_zarp.py
```

The scorer expects `{arm}_{split}.jsonl` for each arm in
`base,placebo,candidate` and split in `sealed,arithmetic`.

## Important limits

This PR does **not** implement a new donor-free weight compiler and does not
claim a passing edit. Closed-form regression on activation targets is still
example-based parameter fitting even without gradient descent: disclose it
if used. The candidate compiler must specify its edit tensors, norms, rank,
calibration leakage checks and how its placebo is generated, before any sealed run.
